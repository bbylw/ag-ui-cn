---
title: 核心能力构建块
description: AG-UI 提供的可组合能力构建块，覆盖流式交互、状态、工具、生成式 UI 与人机协同等场景。
---

AG-UI 将智能体与用户界面的交互拆解为一组可组合的构建块。你可以按产品需求逐步采用，而不必一次性实现全部能力。

## 流式聊天（Streaming Chat）

- **实时输出**：通过 `TEXT_MESSAGE_*` 等事件增量传输内容，提升首字与过程可感知性。
- **多轮会话**：围绕 `threadId` / `runId` 组织连续交互。
- **控制能力**：可结合取消、重试、恢复等机制（具体由客户端与集成实现支持）。

## 多模态（Multimodality）

- 支持类型化附件与实时媒体输入输出（如文件、图片、音频、转录文本等，能力随实现演进）。
- 可携带预览、标注与来源信息，丰富上下文表达。
- 适用于语音助手、文档理解、图像交互等场景。

## 生成式 UI（Generative UI）

AG-UI 支持将智能体输出映射为用户界面：

- **静态/受控生成式 UI**：模型输出结构化数据，由应用使用预定义组件渲染，安全性与一致性更高。
- **声明式生成式 UI**：智能体提出 UI 结构与约束，应用校验后挂载，兼顾灵活性与可控性。

实际采用方式取决于客户端框架与集成能力；可与共享状态、工具调用结合实现动态交互面板。

## 共享状态（Shared State）

- 在智能体与应用之间同步结构化状态（只读或读写）。
- 通过 `STATE_SNAPSHOT` 与 `STATE_DELTA`（JSON Patch）实现高效更新。
- 支持协作式体验，如实时表单、计划看板、进度面板等。

详见：[状态管理](/concepts/state/)。

## 工具调用与结果渲染

- **后端工具**：展示调用过程、参数与执行结果，提升透明度与可调试性。
- **前端工具**：由智能体请求、在客户端执行的动作，并将结果回传继续推理。
- **流式工具输出**：对长耗时任务实时展示日志或中间产物（视实现支持）。

详见：[工具调用](/concepts/tools/)。

## 思考步骤与过程可视化

- 通过推理相关事件与步骤事件展示智能体的中间过程与进展。
- 目标是提供可理解的“正在做什么”，而非暴露原始内部思维链细节。
- 可与活动事件（`ACTIVITY_*`）结合呈现计划、搜索、分析等结构化进度。

## 人机协同（Human-in-the-loop）

- 通过中断机制在关键节点暂停执行，请求用户批准、编辑、选择或补充信息。
- 在保持运行上下文与状态连续性的前提下引入人工控制。
- 适用于审批流、高风险操作、数据确认与交互式澄清。

详见：[人机协同与中断](/concepts/interrupts/)。

## 子智能体与组合

- 支持嵌套委派与多智能体协作场景。
- 通过子智能体事件跟踪生命周期与输出归因，便于在 UI 中区分不同执行单元。
- 可结合作用域状态、追踪与取消能力构建复杂工作流。

## 智能体引导（Steering）

- 允许用户在运行过程中提供实时反馈或新指令，引导智能体调整行为与目标。
- 有助于在长任务中快速纠偏，减少重新发起任务的成本。

## 自定义事件与扩展

- `CUSTOM` 与 `RAW` 事件为协议未覆盖的业务需求提供扩展通道。
- 建议在扩展时尽量保持与标准事件语义兼容，并为客户端提供清晰的处理约定。

## 能力落地建议

1. **MVP**：生命周期 + 文本流式消息。
2. **可观测**：加入步骤/工具调用展示与错误处理。
3. **协作**：引入共享状态与前端工具。
4. **可控**：加入中断审批与引导能力。
5. **增强体验**：按需接入生成式 UI、活动/推理可视化与子智能体。
