# 域名

Kiri 可以为容器提供本地域名，方便在浏览器或工具中通过名称访问服务，而无需记忆动态端口映射。

## 两种域名形式

- **`<name>.kiri.localhost`**：无需额外系统配置即可使用（依赖 localhost 解析行为），适合快速访问。
- **`<name>.kiri.local`**：需要在 Kiri 中开启相应支持后使用，适合作为更“正式”的本地域名。

其中 `<name>` 通常为容器名。对于 Compose 服务，还可使用：

- **`<service>.<project>.kiri.local`**（或对应 localhost 形式，视配置而定）

## 启用与端口

- 在 **Settings › Domains** 中可开启/管理域名功能。
- 自 0.2.0 起，可在 **Settings › Domains › Ports** 配置名称解析服务监听的端口（默认 80 和 443）。修改后，访问链接可能包含端口，例如 `http://web.kiri.local:8080`。
- 当某个容器发布并占用了 80 或 443 端口时，该端口上的名称解析可能暂时让出；容器释放端口后会恢复（行为以版本为准）。

## 访问容器

- 若容器内服务监听在已发布端口上，可通过 `http://<name>.kiri.localhost` 或对应域名访问。
- 结合 [HTTPS](/features/https/) 可为本地域名启用受信任的 HTTPS（需安装 Kiri 的本地 CA）。

## 与端口发布的关系

- 域名访问与 `-p host:container` 端口映射可以并存；域名提供更友好的访问入口，端口映射适合需要固定宿主机端口或非 HTTP 协议场景。
- 若域名端口与容器发布端口冲突，请按提示调整设置或容器端口。

## 常见问题

- **无法解析 `.kiri.local`**：确认已在设置中启用，并检查系统 DNS/解析器是否按 Kiri 要求配置。
- **浏览器访问失败**：确认容器正在运行、服务监听地址正确（通常需监听 `0.0.0.0` 而非仅 `127.0.0.1` 容器内回环，视应用而定）、以及端口/协议匹配。
- **链接带端口**：说明域名服务未使用默认 80/443，属预期行为。
