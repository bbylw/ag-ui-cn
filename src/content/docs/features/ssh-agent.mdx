# SSH Agent 转发

Kiri 支持将宿主机上的 SSH agent 转发到容器中，使容器内的 `git`、`ssh` 等工具可以使用你已有的密钥进行认证，而无需将私钥复制进镜像或容器。

## 典型用途

- 在容器内克隆或拉取私有 Git 仓库（如 GitHub/GitLab over SSH）。
- 在构建或运行过程中访问需要 SSH 密钥的内部服务。

## 使用方式

- 确保宿主机上 SSH agent 已运行且已加载所需密钥（例如 `ssh-add -l` 可列出密钥）。
- 按 Kiri/Compose 支持的方式为容器启用 SSH agent 转发（具体参数、挂载点或 UI 选项以当前版本为准）。
- 在容器内验证：

```bash
ssh -T git@github.com
# 或在需要的命令前确认 SSH_AUTH_SOCK 可用
```

## 安全建议

- 仅在需要时启用转发，并限制在可信镜像与命令范围内使用。
- 避免在日志、镜像层或构建参数中泄露密钥材料；SSH agent 转发的目的正是避免私钥落盘到镜像中。
- 在 CI 或共享环境中，优先使用专用部署密钥或短期凭证。

## 常见问题

- **容器内无法连接 agent**：检查宿主机 agent 是否运行、是否有可用密钥，以及 Kiri 是否已正确暴露转发套接字。
- **权限或 known_hosts 提示**：可能需要在容器内配置已知主机或使用合适的 SSH 选项；这与 agent 转发本身是不同层面的问题。
- **多 agent/多密钥**：确认宿主机当前 `SSH_AUTH_SOCK` 指向期望的 agent。
