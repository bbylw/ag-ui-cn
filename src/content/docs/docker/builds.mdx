# 构建

Kiri 支持通过 Docker BuildKit 执行 `docker build` 与 `docker buildx build`，并将构建结果加载到 Kiri 的镜像存储中。

## 基本用法

```bash
# 在当前目录构建
docker build -t myapp:latest .

# 使用 buildx
docker buildx build -t myapp:latest .
```

构建请求由 Kiri 管理的 BuildKit 组件执行；在空闲时相关组件可停止以节省资源，首次使用时可能按需准备构建环境。

## 与其他引擎共存

- 在 macOS 上若同时安装 Docker Desktop，Kiri 可让你选择普通 `docker build` 默认使用哪个构建器。
- 可通过 `kiri build-with docker|kiri` 或 **Settings → Builds** 更改偏好。
- 这不会影响显式指定上下文或通过其他工具链发起的构建，具体以配置为准。

## 缓存与性能

- BuildKit 使用构建缓存加速重复构建；缓存数据占用的空间可在窗口 Builds 视图或通过 Docker 命令管理（视版本支持）。
- 在 Apple Silicon 上，较新版本支持通过 Rosetta 执行 `linux/amd64` 构建，以提升兼容性与速度。

## 窗口中的构建视图

- **Builds** 视图可查看构建历史、步骤与状态。
- 镜像详情可查看层信息与相关操作（如漏洞扫描，视版本功能而定）。

## 常见问题

- **构建很慢或首次卡住**：可能在拉取构建器镜像或准备缓存；检查网络与日志。
- **构建产物找不到**：确认查看的是 Kiri 上下文下的镜像列表（`docker --context kiri images`）。
- **多阶段构建/私有依赖失败**：检查基础镜像可达性、代理设置，以及是否需要 [SSH Agent 转发](/features/ssh-agent/) 或构建密钥。
- **不支持的 BuildKit 特性**：若遇到错误提示，请确认当前 Kiri 版本支持范围并考虑升级。
