# Kubernetes

Kiri 可在本地运行一个单节点 Kubernetes 集群（基于 k3s），并将其作为 kubectl 的 `kiri` 上下文使用，适合本地开发与测试。

## 启动与管理

```bash
# 启动集群
kiri k8s start

# 查看状态
kiri k8s status

# 停止/删除
kiri k8s stop
kiri k8s delete

# 配置（按版本支持的子命令/选项）
kiri k8s set ...
```

- `kiri k8s start` 与 `status` 会在需要时将 `kiri` 上下文写入你的 kubeconfig（在 Linux 上服务以 root 运行时，写入行为可能在启动时不自动完成，以实际版本为准）。
- 在窗口中可通过 Kubernetes 相关视图（Pods、Services、Settings → Kubernetes）进行查看与管理（视平台与版本）。

## 使用 kubectl

```bash
kubectl --context kiri get nodes
kubectl --context kiri get pods -A
kubectl config use-context kiri
```

确认当前上下文指向 `kiri` 后，即可像使用本地集群一样部署清单、运行服务与调试。

## 与容器运行时的关系

- Kiri 同时提供 Docker Engine API 与 Kubernetes 能力；两者面向不同工作流，可按需使用。
- 集群组件与工作负载会占用额外资源；不使用时可停止集群以减少开销。

## 存储与 hostPath（版本能力）

较新版本支持在 Kubernetes Pod 中通过 `hostPath` 访问宿主机目录（例如 Windows 下 `/mnt/c`、`/mnt/d`，macOS 下 `/Users`，Linux 下 `/home` 等，具体路径与生效条件以版本说明为准）。启用相关能力后可能需要重启集群。

## 兼容性说明

- Kiri 提供的是本地单节点集群体验，适用于开发测试；生产集群特性、网络策略与存储类支持范围以实际版本为准。
- 部分依赖特定内核/容器运行时行为的工具（如 kind、Cilium 等）在不同版本与平台上的兼容性持续改进；遇到问题请参考 [更新日志](/guide/whats-new/) 与诊断信息。

## 故障排查

- 使用 `kiri k8s status` 与 `kiri diag logs` 查看集群与引擎状态。
- 若 kubectl 无法连接，检查 kubeconfig 中 `kiri` 上下文是否存在且指向正确端点。
- 集群启动失败时，确认 Kiri 引擎已运行且系统资源充足。
