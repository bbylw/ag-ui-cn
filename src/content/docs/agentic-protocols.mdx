## 智能体协议（Agentic Protocols）

智能体生态正围绕一组开放、互补的协议快速组织起来——每个协议解决交互中的不同层面。AG-UI 已成为 AI 协议版图中的“第三条腿”：

| 层面 | 协议 | 作用 |
| --- | --- | --- |
| **智能体 ↔ 工具与上下文** | **MCP**（Model Context Protocol） | 将智能体连接到工具与上下文——而这些工具本身也正在变得智能体化 |
| **智能体 ↔ 智能体** | **A2A**（Agent to Agent） | 将智能体连接到其他智能体 |
| **智能体 ↔ 用户** | **AG-UI**（Agent–User Interaction） | 通过面向用户的应用，将智能体连接到用户 |

你可以将应用直接通过 **AG-UI**、**MCP** 与 **A2A** 连接到智能体。AG-UI 可以理解为“厨房水槽式（kitchen sink）”协议——它由自下而上的真实需求驱动，目标是构建一流的智能体应用。

这三个智能体协议互为补充，技术目标各不相同；单个智能体可以、也经常会同时使用三者。

## AG-UI 与 MCP、A2A 的握手（Handshakes）

AG-UI 贡献者已加入握手能力，使 AG-UI 能够通过 MCP 与 A2A 协议“前置代理（front for）”智能体。这意味着 AG-UI 客户端应用与库可以无缝使用支持 MCP 和 A2A 的智能体。

AG-UI 的使命是支持现代智能体应用所需的完整构建块集合。

## 生成式 UI 规范

近期发布了多个[生成式 UI 规范](/concepts/generative-ui/)（包括 MCP-UI、Open-JSON-UI 与 A2UI），允许智能体通过交互协议交付 UI 控件。AG-UI 与这些规范均可协同工作，详见[生成式 UI](/concepts/generative-ui/)页面。

## 如何选择

- 需要让智能体访问工具、工作流与数据源 → **MCP**
- 需要多个智能体跨分布式系统协作与共享任务 → **A2A**
- 需要把智能体的实时过程、状态与交互呈现给最终用户 → **AG-UI**

实践中，一个典型系统会同时使用三者：智能体通过 MCP 调用工具、通过 A2A 委派给其他智能体，并通过 AG-UI 与用户界面保持双向交互。
