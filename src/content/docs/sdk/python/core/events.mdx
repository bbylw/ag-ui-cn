# 事件

AG-UI Python SDK 采用流式事件架构。事件是智能体与前端之间通信的基本单位。

## BaseEvent

```python
from ag_ui.core import BaseEvent

class BaseEvent(ConfiguredBaseModel):
    type: EventType
    timestamp: Optional[int] = None
    raw_event: Optional[Any] = None
    metadata: Optional[Dict[str, Any]] = None
```

`metadata` 按 key 开放：任意 JSON 值（含 `None`）。对象可缺省，但存在时永不为 `None`——显式 `null` 读回为缺省，因此普通 `model_dump_json()` 可往返。`EventEncoder` 使用 `exclude_none=True`，缺省的对象会从线上省略而不是输出 `null`。`ag-ui` 键保留给 AG-UI 自用。

## 生命周期事件

```python
class RunStartedEvent(BaseEvent):
    type: Literal[EventType.RUN_STARTED]
    thread_id: str
    run_id: str
    parent_run_id: Optional[str] = None
    input: Optional[RunAgentInput] = None
```

| 属性 | 说明 |
| --- | --- |
| `thread_id` / `run_id` | 会话线程与运行标识 |
| `parent_run_id` | 分支／时间旅行的谱系指针；若存在，指向同一线程中更早的运行 |
| `input` | 本次运行发给智能体的确切输入载荷；可省略历史中已有的消息 |

## 文本消息事件

```python
class TextMessageStartEvent(BaseEvent):
    type: Literal[EventType.TEXT_MESSAGE_START]
    message_id: str
    role: Literal["assistant"]

class TextMessageContentEvent(BaseEvent):
    type: Literal[EventType.TEXT_MESSAGE_CONTENT]
    message_id: str
    delta: str  # 非空字符串

    def model_post_init(self, __context):
        if len(self.delta) == 0:
            raise ValueError("Delta must not be an empty string")

class TextMessageEndEvent(BaseEvent):
    type: Literal[EventType.TEXT_MESSAGE_END]
    message_id: str
```

### TextMessageChunkEvent

```python
from ag_ui.core import TextMessageChunkEvent

class TextMessageChunkEvent(BaseEvent):
    type: Literal[EventType.TEXT_MESSAGE_CHUNK]
    message_id: Optional[str] = None  # 消息的首个 chunk 必须提供
    role: Optional[TextMessageRole] = None  # JS 客户端中默认 assistant
    delta: Optional[str] = None
```

行为：

- **便捷**：部分消费者（例如 JS/TS 客户端）会把 chunk 事件展开为标准 start/content/end 序列，因此生产者可省略显式的 start/end。
- **首块要求**：消息的第一个 chunk 必须包含 `message_id`。
- **流式**：同一 `message_id` 的后续 chunk 是内容片段；完成会在执行展开的客户端触发隐式结束。

## 子智能体事件

`subagent_run_id` 标识**一次调用**，而不是可复用的定义。字段名在 Python 中为 snake_case，序列化后为 `subagentRunId`。完整模型见[子智能体](/concepts/subagents/)。

```python
class SubagentStartedEvent(BaseEvent):
    type: Literal[EventType.SUBAGENT_STARTED]
    subagent_run_id: str
    name: str
    description: Optional[str] = None
    parent_subagent_run_id: Optional[str] = None
    parent_tool_call_id: Optional[str] = None
    parent_message_id: Optional[str] = None

class SubagentFinishedEvent(BaseEvent):
    type: Literal[EventType.SUBAGENT_FINISHED]
    subagent_run_id: str
    result: Optional[Any] = None
    outcome: Optional[SubagentFinishedOutcome] = None

class SubagentErrorEvent(BaseEvent):
    type: Literal[EventType.SUBAGENT_ERROR]
    subagent_run_id: str
    message: str
    code: Optional[str] = None
```

`outcome` 为 `SubagentFinishedSuccessOutcome` 与 `SubagentFinishedSuspendedOutcome`（可带 `interrupt_ids`）的判别联合；`None` 表示成功（旧读法）。

### 其它事件上的归因

大多数事件类型接受可选 `subagent_run_id`。不带该字段的事件属于父智能体。`RunStartedEvent`、`RunFinishedEvent`、`RunErrorEvent` 不可归因——它们描述整个运行。`MessagesSnapshotEvent` 改为逐消息归因。`StateSnapshotEvent` 与 `StateDeltaEvent` 可归因，但那是来源记录而非所有权：状态始终是运行级的。

## 事件判别

```python
from ag_ui.core import Event

Event = Annotated[
    Union[
        TextMessageStartEvent, TextMessageContentEvent, TextMessageEndEvent,
        ToolCallStartEvent, ToolCallArgsEvent, ToolCallEndEvent, ToolCallResultEvent,
        StateSnapshotEvent, StateDeltaEvent, MessagesSnapshotEvent,
        ActivitySnapshotEvent, ActivityDeltaEvent,
        RawEvent, CustomEvent,
        RunStartedEvent, RunFinishedEvent, RunErrorEvent,
        StepStartedEvent, StepFinishedEvent,
        ReasoningStartEvent, ReasoningMessageStartEvent, ReasoningMessageContentEvent,
        ReasoningMessageEndEvent, ReasoningMessageChunkEvent, ReasoningEndEvent,
        ReasoningEncryptedValueEvent,
    ],
    Field(discriminator="type"),
]
```

Pydantic 在解析时据此选择正确的模型，同时提供静态类型检查。
