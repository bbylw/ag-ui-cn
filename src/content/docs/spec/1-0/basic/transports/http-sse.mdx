---
title: HTTP + Server-Sent Events
description: 1.0 默认绑定：POST 携带运行输入，text/event-stream 携带运行。
---

默认绑定。应用把运行输入 POST 到智能体端点；响应是承载该运行的 [Server-Sent Events](https://html.spec.whatwg.org/multipage/server-sent-events.html) 流。

## 请求

- 客户端向智能体端点发送 `POST`。主体是 [`RunAgentInput`](/spec/1-0/basic/run-input/) 作为单个 JSON 对象，UTF-8 编码，`Content-Type: application/json`。
- 客户端发送 `Accept: text/event-stream`（当也能消费 [protobuf 媒体类型](/spec/1-0/basic/transports/http-protobuf/)时一并添加）。

## 响应

- 开始的运行以 `200` 和 `Content-Type: text/event-stream` 作答。
- 每个 SSE 事件的 `data` 载荷恰好是一个协议事件的 JSON 对象——绝不多于一个，绝不是片段。多行 `data:` 字段按 SSE 规定拼接。
- 生产者 MUST 使用 LF（`\n`）行结束符成帧。SSE 语法也允许 CR 与 CRLF，但本绑定固定使用每个消费者都已知可解析的形式；消费者 MAY 额外接受完整语法。
- 消费者 MUST 忽略 `data` 之外的 SSE 字段（`event:`、`id:`、`retry:`），并 MUST 容忍 SSE 注释行（`: keep-alive`），生产者 MAY 以任意频率发送。
- 生产者在最后一次运行的终止事件后关闭响应体。

一次 POST 携带一次请求；当生产者在被请求运行之前重放线程历史时，一个响应 MAY 仍携带[多次运行](/spec/1-0/events/lifecycle/#单流多运行)——按[绑定契约](/spec/1-0/basic/transports/#绑定契约)，这些运行没有进一步输入。

## 错误

- 运行开始前被拒绝的输入——JSON 格式错误、验证失败、认证被拒——是 HTTP 错误状态且没有事件流。运行从未开始。
- 流开启后的失败在流内以 `RUN_ERROR` 传输。HTTP 状态已经发送且无法更改；消费者 MUST NOT 仅从 `200` 推断成功。
- 没有终止事件就断开的连接是[截断运行](/spec/1-0/basic/transports/#截断)。

## 没有恢复

本绑定没有流恢复：不使用 SSE 的 `Last-Event-ID` 机制，断开的流无法重新进入。重新运行是一次带新 `runId` 的新运行，其输入携带消费者保留的内容。

## 示例

```http
POST /agent HTTP/1.1
Content-Type: application/json
Accept: text/event-stream

{"threadId":"thr-1","runId":"run-1","messages":[…]}

HTTP/1.1 200 OK
Content-Type: text/event-stream

data: {"type":"RUN_STARTED","threadId":"thr-1","runId":"run-1"}

data: {"type":"TEXT_MESSAGE_START","messageId":"msg-1","role":"assistant"}

data: {"type":"TEXT_MESSAGE_CONTENT","messageId":"msg-1","delta":"Hello."}

data: {"type":"TEXT_MESSAGE_END","messageId":"msg-1"}

data: {"type":"RUN_FINISHED","threadId":"thr-1","runId":"run-1"}
```
