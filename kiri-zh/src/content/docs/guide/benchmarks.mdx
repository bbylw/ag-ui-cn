# 基准测试

本文汇总 Kiri 在特定环境下的性能测量结果。实际表现会因机器、镜像、网络与负载而异。

## 测试环境与方法（示例）

- 硬件：Apple Silicon Mac（具体型号/内存以官方发布页为准）
- 操作：`docker run --rm alpine true`（从已有本地镜像创建、运行、退出并删除容器）
- 指标：多次运行取中位数（p50），并可能记录 p99
- 对比：同一台机器、同一 `docker` CLI，在相近条件下分别驱动不同引擎

## 典型结果

在官方文档示例测量中（bridge 网络，p50，30 次）：

| 路径 | Kiri | Docker Desktop（示例） |
| --- | --- | --- |
| 通过 Docker Engine API | ~2.55 ms | ~213 ms |
| 通过 `docker` CLI | ~14 ms | ~243 ms |

在 `--network none` 等不同条件下数值会变化；CLI 路径的耗时中包含 `docker` 客户端自身启动开销。

## 如何解读

- **API 路径** 更接近引擎与运行时本身的开销。
- **CLI 路径** 包含客户端解析、连接与输出等额外成本。
- Kiri 通过缩短 API 之后的执行链路（无 dockerd/containerd/shim/runc 层叠）降低容器创建与启动开销。

## 注意事项

- 不同版本、不同宿主机负载与后台任务会影响结果。
- 首次拉取镜像、冷启动 VM、构建缓存状态等因素不应与热路径混淆。
- 若需复现，请固定镜像版本、网络模式、运行次数与统计方法，并记录系统状态。

更多架构背景见 [工作原理](/guide/how-it-works/)。
