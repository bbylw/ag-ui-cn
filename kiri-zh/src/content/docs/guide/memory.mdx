# 内存与休眠

Kiri 的目标之一是在不牺牲容器体验的前提下减少后台资源占用，尤其是在 macOS 上通过轻量 VM 运行 Linux 容器时。

## 按需使用内存

- 在 macOS 上，Kiri 的 VM 使用**内存气球（balloon）**机制，使 VM 占用尽量贴近容器实际使用量，而不是长期固定占满分配上限。
- 当容器释放内存后，可回收的内存可归还给宿主机（具体行为取决于系统与版本）。

## 自动休眠与唤醒

- 当**没有容器运行**且空闲一段时间（文档示例约 60 秒）后，VM 会自动关机（休眠），从而释放其占用的内存与 CPU。
- 下次执行需要引擎的操作（如 `docker run`、拉取镜像、构建等）时，守护进程会重新启动 VM。
- 唤醒通常很快（示例约 0.1 秒量级），对日常交互影响较小。

## 与传统桌面方案的差异

- 传统方案常驻较重的后台进程与固定开销；Kiri 倾向于“无工作则轻量/休眠”。
- 守护进程本身在宿主机侧保持较小 footprint，并在 VM 内避免为每个容器保留 shim 进程。

## Linux 与 Windows

- **Linux**：直接运行在宿主机内核上，不存在 macOS 那样的 VM 休眠/气球模型；资源占用主要取决于守护进程与运行中的容器。
- **Windows**：引擎运行在 WSL2 环境中，其资源行为受 WSL2 与 Kiri 共同影响；空闲与唤醒表现以实际版本为准。

## 实践建议

- 若希望尽快释放资源，可停止不需要的容器并等待空闲休眠触发。
- 长时间运行的服务（数据库、开发依赖等）会阻止休眠，这是预期行为。
- 若遇到唤醒后首个命令稍慢，通常与冷启动/镜像准备有关，可结合日志与诊断命令排查。
