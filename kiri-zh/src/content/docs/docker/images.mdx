# 镜像与 Rosetta

Kiri 支持 OCI/Docker 镜像的拉取、存储与运行，并在 Apple Silicon Mac 上通过 Rosetta 支持运行 `linux/amd64` 镜像。

## 拉取与管理

```bash
# 拉取镜像
docker pull nginx:alpine

# 列出镜像
docker images

# 删除镜像
docker rmi nginx:alpine
```

- 镜像按内容寻址分层存储，相同层可在镜像间去重。
- 窗口中的 Images 视图可搜索 Docker Hub（视版本）、查看拉取进度与取消拉取。

## 多架构与 `--platform`

```bash
# 指定平台运行/拉取
docker run --rm --platform linux/amd64 alpine uname -m
docker pull --platform linux/arm64 alpine
```

- 在 Apple Silicon（arm64）主机上，`linux/arm64` 镜像原生运行；`linux/amd64` 镜像可通过 **Rosetta** 转译运行。
- 在 Intel Mac 上，`amd64` 镜像原生运行。
- 较新版本中，amd64 **构建**也可在 Apple Silicon 上通过 Rosetta 执行（提升兼容性与速度，视版本而定）。

## 导入与导出

```bash
# 保存与加载镜像
docker save -o image.tar myimage:tag
docker load -i image.tar
```

`docker load` 兼容来自 podman 或较旧 Docker 保存的镜像格式（以版本支持为准）。从 Docker Desktop 迁移镜像可使用 `kiri import`，见 [迁移](/docker/migrate/)。

## 存储位置与清理

- 镜像数据存储在 Kiri 的数据目录（macOS 通常位于 `~/Library/Application Support/Kiri/`）。
- 可使用 `docker image prune`、`docker system df` 等命令查看与清理空间（`system df` 在较新版本中显示真实大小）。

## 常见问题

- **拉取失败**：检查网络、代理设置与镜像源可达性；Kiri 会在可能时给出更具体的失败原因（代理拒绝、限流、需登录等）。
- **amd64 镜像运行异常**：尝试更新到最新版本（Rosetta/内核能力持续改进），或使用对应架构镜像。
- **构建后找不到镜像**：确认构建结果已加载到 Kiri 上下文（`docker --context kiri images`）。
